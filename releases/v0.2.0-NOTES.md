# Chess Database API v0.2.0 — draft release notes

This release is planned and has not been published. It adds game, position, player and event search, exact filtered Opening Explorer statistics, snapshot-bound pagination, and portable search-index companions. The canonical executable and image identity are `chess-database` and `chess-database-api`; the documented legacy CLI, environment, image and network aliases remain available. See [Naming migration](https://github.com/Nerver-zip/chess-database-api/blob/main/docs/NAMING_MIGRATION.md) and [Search API](https://github.com/Nerver-zip/chess-database-api/blob/main/docs/SEARCH_API.md).

Existing CGB3/v1 shards, CPI/v2 indexes, `games.idx`, stable game IDs and canonical dataset releases remain compatible. Search-index format 1 is additive and tied to a canonical corpus fingerprint. Masters OTB R3 and Elite Online R1 remain separate datasets; their software, canonical data and search companion versions are independent. Masters discovery remains disabled by default. Dataset licensing and attribution are separate from the MIT OR Apache-2.0 software license.

For an existing CPI-only installation, retain the original snapshot, upgrade the software, install a matching verified search companion or build the index locally, then reload and check collection capabilities. Use the staged rollback procedure in [Dataset releases](https://github.com/Nerver-zip/chess-database-api/blob/main/docs/DATASET_RELEASES.md). Follow [Docker deployment](https://github.com/Nerver-zip/chess-database-api/blob/main/docs/DOCKER_DEPLOYMENT.md) for read-only mounts, updates and rollback.

Native constrained two-collection Docker testing passed its startup, discovery, mixed-traffic, reload, rollback and feature-control checks at 512 MiB and two CPUs; filtered searches returned busy responses under concurrent load. Two native eviction-advised legacy comparisons and an identical-binary control passed the timing gates with client and server on separate physical cores. These measurements used a shared host and best-effort eviction; earlier noisier failures remain recorded. The final release must reference the reviewed merged commit and include only artifacts verified for their supported platform.

For distribution, GitHub can provide source archives from the reviewed release tag. A Linux x86-64 CLI binary and a container image should be attached or published only after they are built from that merged tag and verified on their supported runtime; the local release build and local Compose image are preparation evidence, not official release artifacts. The repository has no existing container-publishing workflow, so no registry image reference is available yet. Until one is published, build the image locally using the deployment guide. Do not infer cross-platform support from the native x86-64 build.

A local preparation build extracted from the pinned Debian Bookworm image ran on the x86-64 host and passed an Elite CPI-only API probe. Its ELF imports glibc symbols through 2.34 and requires `libgcc_s.so.1`; this is not a universal Linux compatibility guarantee. The pinned image uses glibc 2.36. The extracted binary is pre-merge evidence only; rebuild and verify any release asset from the reviewed tag. See [distribution preparation evidence](https://github.com/Nerver-zip/chess-database-api/blob/main/benchmarks/search/NATIVE_SOFTWARE_DISTRIBUTION_PREPARATION.json).
